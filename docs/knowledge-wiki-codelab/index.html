This codelab walks through my repo, which holds Anthropic's knowledge-wiki quickstart (from anthropics/claude-quickstarts, MIT license) and a small web demo on top of it.

The idea, simply: instead of rereading a whole filing cabinet for every question, an agent reads it once and writes a well-sourced binder. Later questions are answered from the binder.

What you'll build

  • A knowledge wiki: plain markdown pages in a Managed Agents memory store, built from the SEC filings of a real take-private deal (Squarespace). Every fact carries its source and the date it was true.
  • A small FastAPI page that asks the wiki a question and shows the answer, its sources, and what it cost.

What you'll learn

  • How one Managed Agents session runs a whole multi-agent workflow (extract, resolve, analyze, organize).
  • How to check what actually ran, from the platform's own records, instead of trusting an agent's report.
  • How to ask the wiki read-only, and how its cost compares with searching the raw documents.
  • How to keep a paid run from going wrong: budgets, clean-up, and the mistakes I made.

What you'll need

  • A Mac or Linux machine with Python 3.11 or later.
  • An Anthropic API key with Managed Agents access.
  • API credit. The build is a paid run: in my run the notebook estimated $25.77 before starting and the platform metered $18.86. Have more credit than the budget you set.

The notebook does two things.

Build (once). One Managed Agents session runs one dynamic workflow, described in one message to a lead agent. The lead agent starts other agents in four phases:

  1. Extract: one wiki-extractor per batch of documents files what the documents say into the wiki.
  2. Resolve: one wiki-resolver works through the wiki's open questions.
  3. Analyze: one wiki-analyzer per batch re-reads it against the wiki and adds what was missed.
  4. Organize: one wiki-organizer tidies the whole wiki and its index.

The phases really are a sequence: each starts only after every agent of the previous one has finished.

Ask (many times). Each question opens a fresh session with the wiki mounted read-only, so asking can never change the wiki. The analyst agent may only read, glob and grep.

The last line should print a version starting with 2. (the requirements pin anthropic>=2.0.0,<3).

If you use conda, run conda deactivate first so the venv's Python is the one you get.

Create a file named .env in the repo folder. It is in .gitignore, so it never gets committed.

ANTHROPIC_API_KEY=sk-ant-...
COOKBOOK_BUDGET_USD=30
COOKBOOK_RECORDS_DIR=/full/path/to/a/folder/outside/the/repo
  • COOKBOOK_BUDGET_USD caps the build. It must be at least the estimate the notebook prints, and it should be below your credit balance, so the budget stops the build before your credit runs out.
  • COOKBOOK_RECORDS_DIR is where the run's records go. Write the full path: ~ is not expanded. Without it, records go to a temporary folder that may be cleared on restart.

The fetch script reads your SEC contact from the shell, not from .env:

Run the export cell (it saves every question session's transcript to the records folder), then the clean-up cell. By default it keeps the wiki store and removes everything else:

Kept the wiki store: memstore_.... To delete it later: client.beta.memory_stores.delete('memstore_...')

Copy that store id: the demo needs it. Afterwards, created.json in the records folder should list only the wiki store.

The demo asks the kept wiki from a browser. Each question gets a fresh read-only session, which the app archives as soon as the answer is in, and interrupts first if it is still running.

pip install -r demo/requirements.txt
python demo/setup_demo.py

setup_demo.py creates the demo's own analyst agent and environment (no model runs) and prints two lines. Add them to .env with the store id:

WIKI_STORE_ID=memstore_...
DEMO_ENVIRONMENT_ID=env_...
DEMO_AGENT_ID=agent_...

It refuses to run a second time once those ids are in .env, so it can't make duplicates. Then:

uvicorn demo.app:app --host 127.0.0.1 --port 8000

Open http://127.0.0.1:8000, pick one of the example questions, and you'll get the answer with each source shown as a tag, and the reads, tokens, cost and time below it. The answer is inserted into the page as text, never as HTML, because it comes from documents an agent read.

When you're done:

python demo/teardown_demo.py

It archives the demo's agent and environment and keeps the wiki.

The build stopped with

billing_error

. My first two builds ran out of credit partway and left nothing usable. Have more credit than COOKBOOK_BUDGET_USD before starting, and keep the budget below your balance.

A second set of everything appeared. Restarting the kernel after the schema cell starts a new records folder and creates a new environment, store and agents; rerunning the consolidation-prompts cell creates the agents again. Every records folder's created.json lists what that attempt created, so you can archive the agents, sessions and environments and delete the uploads and stores it lists before trying again.

An interrupted question left a session open. The notebook's ask has no clean-up of its own, so an interrupted question's session stays open until the clean-up cell. The demo app closes its sessions in a finally block instead.

You built a wiki once, checked it against the platform's records, asked it questions read-only, compared its cost with searching the raw documents, and put a small web page on top.
